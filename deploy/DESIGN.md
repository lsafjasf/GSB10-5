# 部署顺序依赖推导 — 规则与依据

## 依赖分级规则

| 级别 | 语义 | 是否参与排序 | 冲突时处理 |
|------|------|--------------|------------|
| strong 强依赖 | b 必须完整部署后 a 才能开始 | 硬约束，参与分层 | 成环时断边拆解，断边记入 `cut_edges` |
| weak 弱依赖 | 期望 b 先于 a，允许违反 | 软约束，仅采纳与强依赖分层方向一致者 | 冲突者记入 `weak_deferred` 并报告 |
| optional 可选依赖 | 运行期特性开关，部署期无要求 | 不参与排序 | 仅列入报告 `optional` |

依据：
- **强依赖**是正确性约束（如服务启动时要连数据库），违反即故障，因此必须体现在层序里；成环说明不存在满足全部约束的顺序，只能显式断边换取可执行方案。
- **弱依赖**是优化项（如希望配置中心先就绪以减少重试），违反只影响体验不影响正确性，因此只做"不添乱"的采纳：采纳条件为 `layer[b] < layer[a]`，该条件下加入弱边不会改变最长路分层（归纳可证：新边终点层号已大于起点层号+1 之外的任何候选），保证绝不引入环。
- **可选依赖**按定义组件可在其缺失时运行（功能降级），对部署顺序零约束，只影响运行期特性开关，故完全排除在排序之外。
- 同一对组件出现多种依赖时，按 strong > weak > optional 取最高级别，避免低级别边重复或干扰。

## 分层与并行依据

无环时用 Kahn 最长路分层：组件 x 的层号 = 以 x 为终点的最长强依赖链长度。
因此任意强依赖边 (a 依赖 b) 都满足 `layer[b] < layer[a]`，**同层组件之间不存在任何强依赖边**，
互相无先后约束，可以安全并行部署；层与层之间严格串行。

## 成环拆解规则

1. 自环 (a 依赖 a) 直接断开。
2. 对强依赖图求 Tarjan 强连通分量（迭代实现，避免深链递归溢出），每个大小 > 1 的分量即一个环。
3. 分量内用 Eades-Lin-Smyth 贪心启发式求近似最小反馈边集：反复摘除源点/汇点，
   否则移除出度−入度最大的节点；最终顺序中反向的边即为断开边。
4. 断边后分量内部重新分层，得到"分几步部署"；全局再统一分层。
5. 断开边 (a, b) 的影响组件是依赖方 a：它必须先于强依赖 b 启动，
   需要降级启动（跳过重试/懒连接），待 b 上线后恢复。影响清单见 `BreakPlan.affected`。

## 可校验性

`validate(graph, plan)` 独立重算并核对：
- 每条未断开的强依赖都满足 `layer[b] < layer[a]`（违例逐条列出）；
- 断边数 + 满足数 = 强依赖总数（无遗漏、无重复）；
- 被采纳的弱依赖同样满足先后关系；
- 每个组件恰好出现在一层。
全部通过时 `ok=True`。校验器对被人为破坏的计划能报出具体违例边（见自测 `test_validator_catches_tampered_plan`）。

## 运行命令

```bash
cd deploy
python3 -m unittest test_deploy_order -v   # 自测（9 个用例）
python3 demo.py                            # 四个场景：线性/宽并行/成环/可选依赖

```

## 实测性能（Python 3.12，10,000 组件 / 39,954 强依赖 / 1 万弱依赖 / 1 万可选依赖）

- 推导耗时：约 320 ms；校验耗时：约 40 ms
- 内存峰值（tracemalloc）：约 14 MiB
- 结果：60 层，最宽层 712 个组件，强依赖 39,954/39,954 全部满足，0 违例
