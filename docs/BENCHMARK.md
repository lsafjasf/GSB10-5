# 性能基准（耗时与内存峰值）

- 机器：x86_64，16 核，Python 3.12.3（WSL2）
- 负载：**1,000,000 行 × 1,000 条表达式 = 1,000,000,000（10 亿）次完整求值**
- 数据：8 列（int/float/bool/string），列式存储，种子 42 固定
- 表达式：类型安全的随机过滤条件（比较 + and/or/not 组合，深度 ≤3），种子 7 固定
- 复现：`python3 tools/benchmark.py 1000000 1000 16`（多核）/ `... 1`（单核）

## 结果

| 指标 | 16 工作进程 | 单进程 |
|------|------------|--------|
| 总求值次数 | 1,000,000,000 | 1,000,000,000 |
| 求值墙钟时间 | **26.47 s** | **147.98 s** |
| 吞吐 | 37,780,099 次/秒 | 6,757,469 次/秒 |
| 单次求值（墙钟） | 26.5 ns | 148.0 ns |
| 单核微基准单次成本 | 154.6 ns（5000 万次采样） | 153.0 ns |
| 数据生成 | 1.31 s | 1.27 s |
| 1000 条表达式解析+编译 | 0.064 s（≈64 µs/条） | 0.046 s |
| 列绑定 | 0.004 s | 0.003 s |
| **内存峰值（父进程 RSS）** | **117.0 MB** | **116.4 MB** |
| 内存峰值（最大 worker RSS） | 113.8 MB | 113.7 MB |
| 数据加载后 RSS | 114.5 MB | 114.2 MB |
| 命中数校验和 | 528,796,365 | 528,796,365（一致 ✓） |

## 说明

- 多进程采用 fork + 写时复制共享列数据，worker 的 RSS 含共享页，因此
  「父进程 + 各 worker」不能简单相加；整体驻留内存约 117 MB（其中数据本体
  约 114 MB，求值过程几乎不分配新内存）。
- 求值器为纯解释执行（闭包树），未借助 `eval`/`exec`/`compile` 代码生成；
  单核约 150 ns/次求值，10 亿次全量单核约 148 秒。
- 两种并行度下命中数校验和完全一致，说明并行拆分不改变求值结果。
