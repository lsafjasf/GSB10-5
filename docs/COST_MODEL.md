# 代价模型：预处理什么时候划算

## 符号

| 符号 | 含义 | 实测值（grid-100k-500k） |
|---|---|---|
| `T_pre` | 预处理一次性代价（时间） | 5.43 s |
| `t_naive` | 朴素 Dijkstra 单次查询（目标点提前终止） | 60.85 ms |
| `t_alt` | 预处理后 ALT(A*) 单次查询 | 14.89 ms |
| `M_idx` | 预处理内存（索引表 2·L·n·8B） | 25.6 MB |
| `q` | 查询次数 | — |

## 总代价

- 不预处理：`T_naive(q) = q · t_naive`
- 预处理：  `T_alt(q)   = T_pre + q · t_alt`

两条都是 `q` 的直线：朴素法过原点、斜率大；预处理法截距 `T_pre`、斜率小。

## 临界点（break-even）

两式相等时：

```
q* = T_pre / (t_naive - t_alt) = 5.433 / (0.060851 - 0.014889) ≈ 118.2
```

- **q ≤ 118：不划算**，预处理的总代价更高（查询省下的时间抵不回预处理开销）。
- **q ≥ 119：划算**，且 q 越大省得越多；q = 100k 时总代价 6085s → 1494s（省 75%）。

临界点只取决于三个实测常数，与图规模无关地外推：换图后重新量 `T_pre / t_naive / t_alt` 即可。

## 内存代价与超限处理

预处理内存上界（构建前即可精确估算，见 `spp.alt.estimate_total_bytes`）：

```
M = 2·L·n·8  (地标距离表，float64)
  + 图 CSR 正/反邻接 (n+1)·8·2 + m·16·2
  + 构建/查询 scratch ≈ n·8 + 2·n·16
```

给定预算 `B`，可负担地标数 `L_max = (B - 固定开销) / (2·n·8)`。三种策略
（`ALTIndex(..., on_exceed=...)`）：

- `reduce`（默认）：自动把 L 降到 `L_max`；`L_max = 0` 时退化为朴素 Dijkstra，结果仍精确。
- `fallback`：直接 L=0（不建索引），等价于不预处理。
- `raise`：抛出 `MemoryBudgetExceeded`，由调用方决定。

三种策略都在**构建前**拒绝/降级，进程不会因 OOM 被杀。

## 复杂度

- 预处理：`2L` 次全图 Dijkstra → `O(L · (m + n log n))` 时间，`O(L·n)` 空间。
- 单次查询：A* 每次展开需 `O(L)` 计算启发式；展开点数实测约为朴素的 3.3%
  （grid 图，L=16），故单查询快约 4 倍。
