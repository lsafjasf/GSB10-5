# 脚注编号规则说明

## 1. 编号分配

1. 预扫描全文，按「页 → 页内行 → 行内引用点」的阅读顺序枚举引用点，
   得到全文顺序号 `seq`（1 起）。
2. 每个脚注（`key`）**第一次**被引用时分配编号：
   `number = 已出现过的不同 key 个数 + 1`，即编号 = 首次引用顺序，从 1 开始。
3. **重复引用不另占编号**：同一 key 的第 2、3…个引用点都显示同一个编号。
   因此“引用点数 ≥ 编号数”，且编号数 = 不同 key 数。
4. 编号在一次排版中全局唯一；没有被任何引用点引用的脚注定义不参与编号。

## 2. 删除与重排

- 删除任意引用点（或包含引用点的整行）后，重新执行预扫描与编号。
- 被删的是某 key 的**重复引用**：该 key 仍有其他引用点，编号不变。
- 被删的是某 key 的**唯一引用**：该 key 退出编号表，其后所有 key 的编号
  全部前移一位，结果仍是连续的 `1..N`，**不留空号**。
- `RefPoint.seq` 是扫描序号，用于“删除前/删除后”逐点对照（见 `REPORT.md` 第 3 节）。

## 3. 页脚区排版

1. 每页分为「正文区」`body_cap` 行和「页脚区」`foot_cap` 行。
2. 脚注正文排在其**首个引用点所在页**的页脚区；同一页对同一 key 的多个
   引用点合并为页脚区**一个条目**，条目尾部回链列出全部引用位置
   （格式 `p页.L行`，同一行多个引用显示为 `×n`）。
3. 脚注正文全文只排一次。之后页面上的重复引用只在正文显示同一个上标编号，
   不再重印条目；其位置仍出现在该脚注首块的回链里，保证“每个引用点都能
   指回同一个编号”。
4. 条目在引用页页脚区放不下时，整条顺延到下一页，编号标记 `(顺延)`，
   回链仍指向真正的引用页。

## 4. 跨页拆分与合并

- 页脚区剩余行数 < 脚注剩余正文行数时，能放几行放几行，余下部分作为
  **续块**顺延到下一页，编号标记 `(续)`。
- 下一页排版顺序：**先排上一页顺延的续块/顺延条目，再排本页新引用的条目**。
- 续块必须与上一块首尾相接（后块 `start` = 前块 `start + 前块行数`）。
- 同一脚注跨页的所有块按顺序拼接，必须与定义正文逐行相等
  （`check_consistency()` 会校验，见 `REPORT.md` 第 2、4 节）。
- 正文行是最小排版单位；真实排版中超过页宽的行应先由上层折行。

## 5. 一致性校验（`check_consistency`）

1. 每个引用点都有对应条目，且正文编号 == 页脚条目编号；
2. 每个引用点都出现在其脚注首块的回链中；
3. 每个有引用的 key 恰好有一个 `start=0` 首块（不重印）；
4. 首块位于首个引用页，或标记了 `carried`（顺延）；
5. 跨页块首尾相接、续块标记正确、合并后等于定义正文；
6. 编号集合恰好为 `1..N`，无空号；
7. 每页页脚行数不超过 `foot_cap`。
