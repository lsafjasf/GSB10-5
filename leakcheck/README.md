# 泄漏检测指纹匹配（leakcheck）

纯 Python 3 标准库实现（`hashlib` + `re` + `collections`），无第三方依赖。

## 文件

- `leakfp.py` — 指纹库：归一化、k-gram 分片、Winnowing 选指纹、倒排索引、DF 套话过滤
- `test_leakfp.py` — 12 项自测
- `evaluate.py` — 召回率 / 误报率评测（固定随机种子，可复现）
- `demo.py` — 改字 / 换序 / 拆散拼接 / 无关 四类改写样例
- `benchmark.py` — 10 万文档建库与查询基准

## 指纹方案

| 环节 | 选择 | 说明 |
|---|---|---|
| 归一化 | 小写 + 正则取 token | 英文/数字按词（`[a-z0-9]+`），中文按单字（`[\u4e00-\u9fff]`）；标点、空白、换行全部丢弃 |
| 分片粒度 | 8-token 滑动 k-gram | 步长 1，相邻分片重叠 7 个 token；8 token 约等于英文一句话/中文 8 个字 |
| 哈希 | BLAKE2b 截 64 位 | 跨进程稳定（不用受 `PYTHONHASHSEED` 影响的内建 `hash`）；64 位空间下 300 万指纹生日碰撞期望 < 0.001 |
| 指纹选择 | Winnowing，窗口 w=6 | 单调队列 O(n)；**数学保证：任意连续 ≥ k+w−1 = 13 个 token 的相同片段至少产出 1 个共同指纹**，指纹数量降到全部分片的约 1/w |
| 索引 | 哈希 → 文档id 倒排表 | 另存每文档指纹数，用于覆盖率计算 |
| 命中判定 | 不同指纹命中数 `matched ≥ 6` | 约等于 40+ token 的实质连续抄袭量；同时返回两个比例供人工研判 |

查询返回两个比例：
- `query_containment = matched / 查询文档指纹数`（被怀疑文档有多少比例来自源文档）
- `source_coverage = matched / 源文档指纹数`（源文档被抄走多少比例）

### 能容忍 / 不能容忍

- **改字、改标点、改空白、大小写**：局部 k-gram 失效，其余不受影响。
- **分散的少量增删改**（实测 5% token 替换 100% 召回）。
- **段落换序**：段落内部 k-gram 原样保留，仅段落接缝失效。
- **拆散后拼到别处**：每个 ≥13 token 的碎片独立贡献共同指纹，多处碎片命中数累加。
- **不能**：大规模同义改写、翻译、摘要等语义级变换（精确指纹的固有边界，需语义指纹）。

## 运行命令

```bash
cd leakcheck
python3 -m unittest -v     # 自测
python3 demo.py            # 改写样例命中
python3 evaluate.py        # 召回率 / 误报率
python3 benchmark.py       # 10 万文档基准（可传参: benchmark.py 文档数 查询数）
```

## 召回率与误报率（`evaluate.py` 实测）

**测试集构造**（固定种子 `SEED=20261005`）：词表 1200 英文伪词 + 常用汉字；
基线库 500 篇（150–400 token，30% 夹带固定套话）；另设 16 条公共套话短句。

| 组别 | 样本 | 报警 | 召回/误报率 | top1 源文档正确 |
|---|---:|---:|---:|---:|
| 完全相同 | 200 | 200 | **100.0% 召回** | 200 |
| 改字 5% | 200 | 200 | **100.0% 召回** | 200 |
| 段落换序（切 5 段打乱） | 200 | 200 | **100.0% 召回** | 200 |
| 拆散拼接（2 段 40–70 token 碎片嵌进新文本） | 200 | 200 | **100.0% 召回** | 200 |
| 无关长文（全新随机） | 500 | 0 | **0.0% 误报** | — |
| 仅含公共套话（1–2 句） | 300 | 0 | **0.0% 误报** | — |
| 短文档（14–60 token，半数含套话） | 300 | 0 | **0.0% 误报** | — |

总体：召回 800/800 = **100.00%**，误报 0/1100 = **0.00%**，命中后 top1 定位 100%。

## 短文档与正常文本的误报控制

三道针对短文本/公共片段的控制：

1. **最小长度拒判**：不足 `k+w = 14` 个 token 的文本直接返回空（指纹少于 2 个，
   任何结论都不可靠）。短文档组 300 篇全部按此处理，误报 0。
2. **绝对命中数门槛 `min_hits=6`**：即使长度够，也必须有 6 个不同的共同指纹
   （约 40+ token 连续实抄）才报警；一两句"如有雷同纯属巧合"级别重合不够。
3. **文档频率过滤 `max_df=8`**：出现在超过 8 篇库内文档中的指纹视为公共套话，
   查询时忽略。真正的泄漏内容 DF 通常为 1–2，而免责声明、版权模板会命中大量文档。
   实测：只共享套话的负例在关闭 DF 过滤时误报 53.7%，开启后降到 0%，而正例召回不变。

调参权衡：`min_hits` 调小→更敏感但套话误报增多；`max_df` 调小→套话过滤更强，
但若库中某源文档存在大量合法转载副本会被当成套话（可对该源文档关闭过滤）。

## 10 万文档性能（`benchmark.py` 实测，本机 Python 3.12）

语料：100,000 篇 × 120 token（约等于每篇一两段短文），词表 3000。

| 指标 | 数值 |
|---|---|
| 建库耗时 | **10.6 s**（0.106 ms/篇，约 9,500 篇/s） |
| 不同指纹数 | 3,157,813 |
| 内存峰值（RSS） | **723 MB**（含 10 万篇原文约 86 MB；纯索引约 640 MB） |
| 查询平均延迟 | **0.14 ms** |
| 查询 p50 / p95 / max | 0.17 / 0.19 / 0.24 ms |
| 查询集 | 500 次（250 次库内原文、250 次全新文本，命中 250 次） |

## 库的用法

```python
from leakfp import LeakIndex

idx = LeakIndex(k=8, w=6, min_hits=6, max_df=8)
idx.add("doc-1", open("source.txt").read())
for m in idx.query(open("suspect.txt").read()):
    print(m["doc_id"], m["matched"],
          m["query_containment"], m["source_coverage"])
```
