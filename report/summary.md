## 不兼容清单与处理步骤

### full_compat — 可回滚
- 无 error 级不兼容项。

处理步骤：
1. 按常规发布流程重新部署旧版本；
2. 回滚后抽查读取日志，确认无解析错误；
3. 后续若恢复新版本，注意新写入数据仍需保持向后兼容。

### additive_fields — 可回滚

  - `tags`（unknown_field）×100000：无需处理：v1 按 ignore 策略丢弃，不影响读取

处理步骤：
1. 按常规发布流程重新部署旧版本；
2. 回滚后抽查读取日志，确认无解析错误；

### new_enum — 需先转换
- 字段/位置：`status`；类型：`unknown_enum`；影响：10000 条；首现行：10；样本：`pending`
  - 说明：取值 'pending' 不在 v1 枚举集合 ['active', 'inactive', 'banned'] 内
  - 处理：回滚前将新枚举值映射为 v1 已知取值（如 pending->inactive），或隔离相关记录

处理步骤：
1. 冻结新版本写入或开启双写，避免转换期间继续产生不兼容数据；
2. 按不兼容清单逐条转换：新枚举值映射回 v1 取值；用 v1 工具链重建索引；
3. 转换后重新运行本验证，确认结论变为“可回滚”；
4. 再部署旧版本，并保留转换前数据快照。

### index_change — 需先转换
- 字段/位置：`index.format`；类型：`index_format`；影响：1 条；首现行：0；样本：`sharded-hash`
  - 说明：v1 仅支持 flat-hash，实际为 'sharded-hash'
  - 处理：回滚前用 v1 工具链将索引重建为 flat-hash v1 格式
- 字段/位置：`index.version`；类型：`index_version`；影响：1 条；首现行：0；样本：`2`
  - 说明：v1 仅支持索引版本 1，实际为 2
  - 处理：回滚前重建索引到 v1 索引版本

处理步骤：
1. 冻结新版本写入或开启双写，避免转换期间继续产生不兼容数据；
2. 按不兼容清单逐条转换：新枚举值映射回 v1 取值；用 v1 工具链重建索引；
3. 转换后重新运行本验证，确认结论变为“可回滚”；
4. 再部署旧版本，并保留转换前数据快照。

### id_type_change — 不可回滚
- 字段/位置：`id`；类型：`type_mismatch`；影响：100000 条；首现行：1；样本：`'u-00000001'`
  - 说明：期望 int，实际 str
  - 处理：字段类型已变更，需要外部映射表或迁移脚本，不能就地简单转换

处理步骤：
1. 禁止直接回滚：旧版本无法读取该数据，直接回滚会导致读取失败/脏数据；
2. 制定迁移方案：外部映射表（新旧 id 对照）、数据迁移脚本或前滚修复 fix-forward；
3. 迁移完成并在预发环境用旧版本读取验证通过前，保持新版本运行。
