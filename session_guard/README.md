# Session Fixation 防护库（Python 3，仅标准库）

## 运行命令

```bash
cd session_guard
python3 selftest.py     # 全部场景自测 + 随机性统计 + 100 万次基准
```

文件：`session_guard.py`（库）、`selftest.py`（自测/基准）。

## 标识更换规则与时机

1. **时机**：仅在**认证成功之后**更换标识。登录前的匿名/预登录标识（即攻击者可能
   预设并诱导受害者使用的那个）在凭证校验通过的瞬间被作废。
2. **原子性**：凭证校验、删除旧标识、生成新标识、迁移会话数据，全部在同一把全局
   锁内完成。不存在“新旧标识同时有效”的窗口，旧标识离开 `login()` 即永久失效，
   不可重放、不可再登录。
3. **失败不换**：认证失败时标识与原会话完全不变，仅 `failed_attempts += 1`，
   允许在同一标识上重试（避免每次失败都强制客户端换标识的可用性问题）。
4. **特权变化即轮换**：每次成功登录（包括已登录用户再次登录）都再次更换，
   `generation` 单调递增，历史标识全部失效。
5. **新标识来源**：`secrets.token_hex(32)` → `os.urandom` → Linux `getrandom()`
   内核 CSPRNG，256 bit 熵，不可预测；生成时检查不与现存标识冲突。
6. **审计**：新会话仅保存旧标识的 SHA-256 指纹（`prev_sid_fingerprint`），
   可审计更换链，但指纹无法反推旧标识、旧标识本身也不再有效。

## 并发与重试的确定行为

- **并发登录同一旧标识**：锁决定的第一个请求完成“校验+更换”；其余请求看到的
  旧标识已被删除，确定性地得到 `InvalidSessionError`。N 个并发 ⇒ 恰好 1 个成功。
- **登录失败后重试**：标识不变、失败计数递增；任意次失败后一旦成功，一次性更换。
- **重放旧标识**：与“标识不存在”同等对待，一律 `InvalidSessionError`。

## 自测验证数据（实测输出摘要）

### 旧标识失效验证（场景 2）

```
旧标识: 8b1540059dfd…   新标识: 3b126e630014…
  第 1~5 次用旧标识访问 -> 拒绝: 会话标识无效或已被作废   (5/5 拒绝)
  用旧标识再次登录       -> 拒绝: 会话标识无效或已被作废
审计指纹: 新会话记录的旧标识 SHA-256 指纹 = be461060ccc82e20
```

### 标识变化轨迹

- 首次登录：`df09053c0f6c…` → `91affe41bb3b…`（generation 0→1）
- 连续 3 次登录：`2eeeb071a96e… → 883cfc0c851c… → 66c643a264fa… → 9438708f9bb1…`
  （4 个标识互不相同，历史标识全部失效）
- 并发 8 线程：`0e0b363c1668…` --原子更换--> `80a1fefe06af…`；
  恰好 1 线程 `OK`，其余 7 线程 `InvalidSessionError`
- 失败重试：`28c914dc2f87…`（失败 ×3，标识不变，failed_attempts 1→3）
  → 第 4 次成功 → `8218ed82bdea…`

### 随机性统计（20,000 个样本）

- 来源：`secrets.token_hex(32)` → `os.urandom` → `getrandom()`（内核 CSPRNG）
- 唯一值 20,000/20,000，碰撞 0
- 比特 1 占比 0.500065（期望 0.5）
- 字节均匀性 chi2 = 219.8（df=255，0.1% 临界值 ≈325）→ 均匀
- 生日界：生成 2^64 个标识的碰撞概率 ≈ 1.47e-39

### 100 万次登录会话操作基准（Python 3.12，每次操作 = 建匿名会话 + 登录换标识 + 销毁）

- 总耗时 **6.20 s**，吞吐 **≈161,000 ops/s**（每次操作含 2 次 CSPRNG 取随机数）
- tracemalloc 堆内分配峰值 **0.8 KiB**；进程 RSS 峰值 **30.5 MiB**（基准前后无增长）
- 结束后存活会话 0 —— 旧标识均即时删除，内存占用有界，不随操作数增长
